# Divergence from upstream

Everything this repo changes relative to [jellyfin/jellyfin](https://github.com/jellyfin/jellyfin) at the ref pinned in `UPSTREAM_REF` (v12.1). The list is the contract: if it's not here, we didn't change it.

Patch numbers are stable across releases: each patch keeps the number it was first given (its `Patch: 00NN` trailer), so gaps are patches that upstream absorbed. Every patch message carries the full Intent, Ceiling and Drop when; the table is the summary.

| Patch | What | Drop when |
|---|---|---|
| `0002-migrations-skip-gate-for-replica-processes.patch` | `JELLYFIN_SKIP_MIGRATIONS=true` turns migration into a checkpoint: zero pending means one info line and a normal start, anything pending fails fast and points at the migration Job (`--mode MigrateSystem`). Pending is counted from the history table, the migrations assembly of the active provider (the PostgreSQL plugin brings its own) and the code migrations of every stage. A gated process applies nothing, so it never runs the post-migration VACUUM/index work either. The pass is remembered per service instance, so an in-process restart after a backup restore checks the restored history again | upstream grows an equivalent gate |
| `0003-items-make-the-ItemValues-get-or-create-concurrency-.patch` | port of upstream PR 17119's goal to `ItemPersistenceService`: new genre/studio/tag values go in through `INSERT ... ON CONFLICT ("Type", "Value") DO NOTHING` in one fixed (Type, Value) order and are re-read, so parallel item saves no longer abort on the unique index and every item maps to the row that actually exists | UPSTREAM_REF contains PR 17119 |
| `0004-replication-leader-gate-background-work.patch` | `JELLYFIN_ROLE` unset or `leader` behaves like stock; any other value disarms scheduled task triggers, trigger-originated scans and LiveTV/DVR timer arming, with one startup log line naming the role. Manual API-invoked runs work on any pod | upstream ships first-class multi-instance roles |
| `0005-devices-read-through-to-the-database-on-token-cache-.patch` | a device token cache miss re-checks the database before rejecting, so a token minted on another replica authenticates here | upstream makes the token path DB-backed |
| `0007-users-split-the-user-query-so-sibling-collections-st.patch` | `UserQuery` uses `AsSplitQuery`, so Permissions, Preferences and AccessSchedules stop joining into a cartesian product (~312 rows per user load). Measured 12.13 ms -> 2.27 ms per user load and 70.2 ms -> 4.36 ms for the user list; the two statements were #1 and #2 by cumulative DB time | upstream switches `UserQuery` to a split query |
| `0012-hls-hand-out-the-live-playlist-after-the-first-segme.patch` | the first response of `Videos/{id}/live.m3u8` for a newly started transcode returns once one segment exists instead of waiting for `MinSegments` (2 or 3). Players poll a growing playlist either way; the VOD master/main playlists are untouched | upstream adds its own fast start, or a client stalls on a one-entry playlist |
| `0015-startup-raise-the-thread-pool-worker-floor-in-code.patch` | raises the managed thread-pool worker floor to max(32, current) at startup and logs `Thread pool worker floor raised: A -> B`. `DOTNET_ThreadPool_MinThreads` was deployed and silently ignored while synchronous cache writes stalled API work | the runtime raises its default floor above the core count or logs the effective floor, or upstream sets it |
| `0016-userdata-upsert-saves-so-duplicate-reports-cannot-ra.patch` | `SaveUserData` writes through `INSERT ... ON CONFLICT ("ItemId", "UserId", "CustomDataKey") DO UPDATE`, so duplicate progress/stop reports no longer race into a `PK_UserData` violation (HTTP 500 on `POST /Sessions/Playing/Progress`). Dates are bound through `ToUniversalTime()`, the model converter's own write rule, which the raw statement would otherwise skip | upstream makes `SaveUserData` conflict-safe |
| `0017-items-upsert-provider-rows-so-parallel-saves-cannot-.patch` | an existing item's `BaseItemProviders` rows are upserted through `ON CONFLICT ("ItemId", "ProviderId") DO UPDATE` after 12.x's batched owned-row delete, ordered by (ItemId, ProviderId) across the batch, so two parallel saves of one item no longer abort on `PK_BaseItemProviders` | upstream serialises or upserts provider writes |
| `0018-startup-redact-credential-bearing-values-from-the-en.patch` | the startup environment dump prints `[redacted]` instead of the value for any variable whose name contains `SECRET`, `PASSWORD`, `TOKEN`, `APIKEY` or `API_KEY` (case-insensitive); the name still prints | upstream redacts its own environment dump |
| `0019-mediainfo-drop-unprobed-lossless-audio-direct-play-c.patch` | `GetPostedPlaybackInfo` strips `truehd`, `mlp`, `dts` and `dca` from the direct play profiles of clients that declare them without probing (Android TV / Fire TV), forcing the normal transcode path instead of a DirectPlay that dies in ExoPlayer. EAC3-Atmos is untouched; an entry whose codec list empties out is dropped, not blanked | the Android TV client probes audio decoders (jellyfin-androidtv PR 5645, in the 0.20.0 pre-releases) and the clients in use run it, or Jellyfin gains a server-side per-client audio policy |
| `0020-migrations-materialise-the-ratings-before-MigrateRat.patch` | new at 12.1. `MigrateRatingLevels` (re-dated, so every existing database runs it) wrote while its DISTINCT reader was still open; Npgsql allows one active command per connection and throws, which failed the migration and rolled the database back to the pre-migration dump. The ratings are materialised first | upstream materialises the query |
| `0021-migrations-strip-the-dead-Data-keys-without-SQLite-J.patch` | new at 12.1. `StripEmbeddedLinkedChildren` removed three keys from `BaseItems.Data` with SQLite's `json_remove()`/`json_valid()`, which PostgreSQL does not have (42883), so the migration failed and rolled the database back to the pre-migration dump. The same edit now runs in provider-neutral C# (System.Text.Json, batches of 500, one transaction per batch), proven identical to the SQLite statement on 1,007 rows | upstream rewrites the routine without provider-specific SQL |
| `0022-items-end-every-item-ordering-on-the-id-so-paging-is.patch` | new at 12.1. Every ordering `ApplyOrder` builds ends on the item Id, so it is total. It ended on `SortName`/`Name`, and PostgreSQL's top-N sort orders ties differently for each LIMIT/OFFSET: paging a 5,881-item library 100 at a time on a copy of the production database returned only 5,724 distinct items (10.11 on the same data: all of them) | upstream ends its item orderings on a unique key |
| `0023-startup-exit-non-zero-when-a-migrate-or-seed-run-fai.patch` | new at 12.1. In `--mode MigrateSystem` and `--mode SeedSystem`, a failure in the CoreInitialisation or AppInitialisation stage now ends the process with exit code 1. Upstream logs `Error while starting server`, rolls the database back and exits 0, so a Kubernetes migration Job reported Succeeded after a failed pass. The server mode is unchanged | upstream exits non-zero on a failed one-shot startup mode |

Dropped at 12.1, because upstream absorbed the change or removed the code it targeted:

- `0001` `--mode MigrateSystem|SeedSystem`: was a backport of PR 16319, which v12.1 contains.
- `0006` delete Permissions/Preferences on user update instead of orphaning them: fixed upstream by PRs 17643 and 17645 (issue 17601); v12.1 syncs the collections in place and the foreign keys are required.
- `0008` count the grouping instead of materialising it: PR 16062's ItemCountService replaced the per-folder `Limit=0` grouped count that carried the measured cost. The once-per-page `TotalRecordCount` still counts a grouped query, now in a MIN-based form; the gain there is unmeasured on 12.1.
- `0009` search plain terms with LIKE: PR 16121 moved search into SqlSearchProvider, and PR 16062 moved the query translation; both already emit LIKE.
- `0010` read the Latest date cutoff first: PR 16062 rewrote `GetLatestItemList` to read the cutoff as its own statement.
- `0011` count a season's children in the database: PR 16062 (with 17881 and 18003) serves the counts from batched precomputed queries.
- `0013` and `0014` parallel NextUp probes and lookups: PR 16062 replaced the per-series pipeline with a batched, set-based `GetNextUpEpisodesBatch`.

Image-layer divergence (no server patch involved):

| Layer | What | Drop when |
|---|---|---|
| PostgreSQL client | `postgresql-client-18` from the PGDG repo: the provider plugin's pre-migration backup runs `pg_dump`, which refuses a server major newer than its own | the base image ships a matching client |
| held jellyfin packages | the 12.1 base points its jellyfin apt source at the master channel, so the security upgrade holds `jellyfin-*` to keep the base's tested jellyfin-ffmpeg | the base's apt source points at the stable channel |
| rffmpeg dispatch shims | [rffmpeg](https://github.com/joshuaboniface/rffmpeg) pinned by commit + checksum (no upstream releases), installed as `ffmpeg-dispatch`/`ffprobe-dispatch` with a baked `/etc/rffmpeg/rffmpeg.yml`; routes encodes to an ssh worker with local fallback | Jellyfin grows native remote transcoding |

Ceilings worth knowing:

- Single-node behavior is unchanged by construction: every gate defaults open when `JELLYFIN_ROLE` is unset, the skip-gate only acts when its env var is set, and the dispatch shims sit unused until the encoder path is pointed at them. A stock deployment of this image behaves like the official one.
- The image build compiles the server but keeps the official image's jellyfin-web and jellyfin-ffmpeg; a web or ffmpeg change upstream arrives via the base image bump, not this repo.
- The skip-gate compares the migration history with the migrations assembly, not the runtime model with the schema: a provider whose migrations lag the model passes it.
- Only arming is leader-gated. A run someone asks for (API task execution, the scan queued after a library edit) executes on whichever pod receives the request.
- Token read-through covers misses only: a token revoked on one replica stays valid on another replica that already cached it, until that process restarts.
- 0003, 0016 and 0017 make the writes converge; they do not serialise them. Under a race the provider rows of one item end up as the union of both savers' keys until the next uncontended save, and the sibling image and metadata-field rows stay on delete-then-reinsert.
- 0016 names its columns explicitly: a new upstream UserData column must be added to the statement, or it keeps its default on insert and is never updated on conflict.
- 0022 covers the orderings `ApplyOrder` builds. The people listing, `LibraryManager.Sort` and the NextUp candidate order sort in their own code and keep their own tie handling.
- Env redaction matches by variable name only; a credential inside a value whose name carries no marker (a connection string, a URL) still prints.
- The dispatch path is single-worker with local fallback, not worker HA: rffmpeg load-balances across registered hosts, but this repo's smoke only proves one worker plus fallback. Register more hosts if you need spread.
